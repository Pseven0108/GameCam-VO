# 后续可选设计：固定决策与同调用直接对照

**仅为研究设计。** 这项对照不属于当前八组，不实现、不执行，也不从历史 Task003 回放代替正式 E0 的决策记录。先完成总效应筛选，再根据证据决定要验证哪个 D/W/U 因子和哪一阶段。

1. **建立 E0 决策记录。** 沿用同一有序 487 张 RGB 的哈希清单、原始 ID、输入 K、尺寸、stride、seed、原 R2 配置及权重。按原始 RGB ID 记录两道决策：MotionFilter 是否真正把该帧加入缓存，以及入图后的局部保留/拒绝。分别记录原生运动分数、原生 `video.distance()`、阈值、连续拒绝计数/上限、强制保留、warmup、是否评过该门及分支原因。封存列表、事件序号、代码和配置哈希。一个 slot 在不同时间可重用，不能作为固定录制键。
2. **固定两道决策，保留自然比较。** 在以后单独审查的候选版本中，仍运行原生分数和距离计算，先保存该状态下算法会选择的 `natural_decision`，只在决定是否插入和是否移除候选的分支出口应用 E0 的 `forced_decision`。调用原来的接受/拒绝分支更新缓存、计数和图，不覆写距离、阈值或位姿，不用 GT。记录两者差异和具体原因。E0 要求某输入走一条当前不可执行的分支，或遇到不合法时间戳、缓冲区、不可用状态、warmup 状态不一致，立即标 `REPLAY_INCOMPATIBLE`；不得伪造接受、不重启补跑。
3. **验证干预足够局部。** 先比较自然 E0 与“回放 E0 决策”的 E0 在规定数值容差下的输入序列、阶段计数、去留、图快照、导出与错误状态；记录原生分数仍被实际计算、调用总数以及非分支路径追踪，做 sham 对照。正式对照核对每个时刻进入图的 RGB ID、历史缓存与最终保留帧与 E0 的一致性；允许另外报告由优化器内在反馈导致的差异。固定选帧后，邻近边、目标、权重、阻尼、视差与位姿仍可能变化，该结果只可称“固定选帧条件下的流水线差异”。
4. **直接效应优先用同一 BA 前状态成对比较。** 在决策前或保留后单个已选调用的锁内捕获同一完整调用快照。封存 `poses/disps/K`、完整边与范围 `ii/jj/t0/t1`、完整 `target/weight/eta`、缓存的 `mono_disps/zeros`、U/中间缓冲、DINO 特征及仿射公共状态、原生迭代数、所有阻尼和 ABI 身份。每个分支用从同一快照独立恢复的可写缓冲（含优化器有写入的张量和 scratch），单次改变选定 D、W 或 U，保持相同求解设置。收集 raw native 返回和 clamp 后的 pose/disparity/U，报告局部相机中心位移向量/长度、旋转变化、负值/夹紧数量；对比相同优化窗口和预定端点，使用一致坐标与尺度。用先重放基线、再隔离，对照数据还原公差、重复基线抖动和输入一致性。评估的是**该固定状态下的同调用局部更新**，不推断对整个视频的净效果。

准入条件：E0 决策记录完整、可复算；本机先用合成事件验证回放接口与指针/状态隔离；之后才申请真实状态快照与运行授权。本轮未改 runner、选帧逻辑或运行矩阵，E5-F0 仍独立阻断。
