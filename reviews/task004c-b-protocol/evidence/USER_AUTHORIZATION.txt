# **二、四组交叉实验怎么安排？**

我们可以把产生 S1、S0 的两次自然运行直接作为四组实验中的两组。

这样不用额外跑六次完整实验，只需要四次。

| 实验 | D | 关键帧调度 | 作用         |
| -- | - | ----- | ---------- |
| B1 | 1 | S1    | 自然基准       |
| B2 | 0 | S1    | 固定 S1，切换 D |
| B3 | 1 | S0    | 固定 S0，切换 D |
| B4 | 0 | S0    | 自然基准       |

这样可以回答：

- B1 对 B2：在相同关键帧调度下，D 是否仍然影响结果？
- B3 对 B4：换一套关键帧调度，D 的影响是否仍然存在？
- B1 对 B3：D 开启时，关键帧调度变化有什么影响？
- B2 对 B4：D 关闭时，关键帧调度变化有什么影响？

这就是我们需要的交叉实验。

# **三、必须保存哪些数据？**

这是本阶段最重要的技术要求。

**共同初始化快照不能只有摄像机位置和关键帧 ID。**

必须尽可能完整地保存：

| 数据类别 | 必须保存的内容                            |
| ---- | ---------------------------------- |
| 相机状态 | poses、intrinsics                   |
| 深度状态 | disparities、mono_disps             |
| 网络状态 | context、hidden state               |
| 图像特征 | DINO features、correlation features |
| 不确定性 | U、UBA weights                      |
| 优化变量 | target、weight、eta、affine weights   |
| 图结构  | source/target indices、edge状态       |
| 关键帧  | ID、插入顺序、活动窗口                       |
| 运行状态 | frame index、buffer slot、计数器        |
| 随机状态 | Python、NumPy、PyTorch、CUDA RNG      |
| 环境信息 | 源码、权重、配置、CUDA版本及哈希                 |

还要保存每个张量的 shape、dtype、stride 和 SHA256。

如果有任何关键变量无法恢复，不能把快照标记为完整。

# **四、关键帧调度必须怎样记录？**

不能只记录最终保留了多少帧。

例如：

- S1 最终保留112个关键帧；
- S0 最终保留160个关键帧。

这还不够。

我们需要记录每一帧发生了什么：

1. 是否通过 Motion Filter。
2. 是否进入候选 BA。
3. BA 是否接受。
4. 是否成为关键帧。
5. 是否删除旧关键帧。
6. 新增了哪些图优化边。
7. 删除了哪些图优化边。
8. BA 调用了几次。
9. 每次 BA 使用了哪些 source/target。
10. 当时的图结构和活动窗口是什么。

在交叉实验中，固定的是关键帧事件流、图结构拓扑和 BA 调度；图像残差、位姿、视差及动态计算出的权重仍然由各自分支正常更新。

否则就不是我们要研究的实验了。
