# 磁盘准入与逐组归档

**每组启动前，目标数据盘实测至少 13 GiB 可用**：保持 10 GiB（10,737,418,240 bytes）余量，加上本组 3 GiB（3,221,225,472 bytes）预算，合计 13,958,643,712 bytes。每组都重新测实际可用空间和挂载归属。Task003 历史的 13.65 GiB 不能替代这一测量。当前服务器空间未复测；8 组留在同盘需要按实测滚动判断。

| 操作 | 交付与停止条件 |
|---|---|
| 启动前 | 为当前组建立新 attempt 目录并绑定策略、输入、配置、进程和数据盘。在接收端确认空间与身份。任何一盘不足即停 |
| 运行中 | 记录日志、进度和空间；不得消耗 10 GiB 保留、运行重叠组或复用历史目录。异常停止并保留已有产物 |
| 本组结束 | 验证过程、日志和轨迹；冻结文件清单和字节数，以 SHA-256 封存输出（含失败收据与可用部分证据） |
| 产生归档 | 计入源输出、ZIP 副本和同盘接收副本；检查保守估计覆盖实际峰值。如需分盘，先核验目标空间与身份。失败则保留源输出 |
| 异机接收 | 按单条 attempt 身份传到本地接收目录，保持独立副本；验证归档外层 SHA-256、ZIP CRC、成员清单、成员大小及内部 SHA-256，写独立回执 |
| 下一组 | 上一组运行且接收均通过后，重新检查各盘。归档损坏、传输失败、空间不足一律停止，不跳组、不重试，不自动清理 |

CPU 验证覆盖 `tools/archive.py:17–94` 的清单、写入、复开、独立接收及防止覆盖，以及 `tools/scheduler.py:173` 的同盘峰值核算。8 份本机接收回执见 `evaluation/mock_receiver_03/*.verified.json`；这是两套目录本机模拟，不代表远端传输或 3 GiB 足以覆盖真实输出。归档本身的过程需要检查压缩临时文件和独立接收所占空间，不能用最终 ZIP 大小替代峰值。
