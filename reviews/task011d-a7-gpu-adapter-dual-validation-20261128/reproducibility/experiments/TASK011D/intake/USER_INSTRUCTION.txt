# 2. 第一阶段：A7 GPU Adapter 修复

## 2.1 当前问题

文件：

`reviews/task011c-maxfusion-spatial-utility-20261128/reproducibility/experiments/TASK011C/uniform_control.py`

重点函数：

- `torch_uniform_for_call()`
- `install()`
- `Proxy.ba()`

目前存在以下问题：

```
ix = indices.detach().cpu().numpy()
a = a5.detach().cpu().numpy()
nv = native_valid.detach().cpu().numpy()
d = mono.detach().cpu().numpy()
```

这里的 `a5`、`native_valid`、`mono` 都可能包含整个 Buffer。

当前 Buffer=500，Native disparity 网格为45×80。

每次 BA 调用都将整个 Buffer 的数据传输到 CPU，随后在 CPU 上执行审计。

此外，当前 Proxy 还存在：

- 为整个 Buffer 创建 A5 和 validity Tensor。
- 遍历所有 live frames。
- 对每个 BA 调用重新复制大量非源帧数据。
- 使用逐源帧 `.item()`，可能引起重复 CUDA 同步。

这些操作没有必要。

## 2.2 新实现要求

必须遵循：

**只处理当前 BA 实际使用的源帧，不处理整个 Buffer。**

保留原始数学定义：

[\
kx=\operatorname{unique}\
\left(\
\operatorname{arange}(t_0,t_1)\cup ii\
\right)\
]

[\
M_t(x)=\
(native_valid_t(x))\
\land\
(mono_t(x)>0)\
]

[\
\mu_t=\
\operatorname{Mean}*{x\in M_t}(r*{5,t}(x))\
]

[\
r\_{7,t}(x)=\
\begin{cases}\
\mu_t,&x\in M_t\\\
0,&x\notin M_t\
\end{cases}\
]

其中：

- A5 原始可靠性计算不变。
- 必须使用实际 BA 调用中的 `ii`、`t0`、`t1`。
- 必须使用原始 `slice_h`、`slice_w`。
- 必须在45×80 Native disparity 网格上计算。
- 必须逐源帧独立计算均值。
- 不得使用整张640×360图像的均值。
- 不得把不同源帧混合求均值。
- 不得修改原生有效 Mask。

## 2.3 建议实现架构

将当前全 Buffer 运算改成以下流程。

**步骤 A：取得实际源帧索引**

计算真实 `kx`。

只传输必要的整数索引，不传输图像 Tensor。

**步骤 B：取得源帧时间戳**

只提取 `kx` 对应的时间戳。

禁止：

```
video.timestamp[:live].detach().cpu().numpy()
```

改为只对实际源帧时间戳进行索引和必要的主机端映射。

**步骤 C：GPU 端直接提取 A5 和 Native-valid**

使用时间戳映射取得当前源帧：

```
a5_src = torch.stack([...], dim=0)
valid_src = torch.stack([...], dim=0)
mono_src = args[3].index_select(0, source_slots)
```

以上仅为接口示意，具体实现必须先核对实际 Tensor 形状和设备。

`a5_src`、`valid_src`、`mono_src` 均只包含当前 BA 源帧。

**步骤 D：全部核心计算留在 GPU**

在 GPU 上完成：

- Mask 构造。
- 有限性检查。
- A5 正值支持集检查。
- 每源帧 FP32 均值计算。
- A7 均匀系数构造。
- 均值匹配检查。
- 正值支持集一致性检查。

尽量批量化计算。

禁止逐像素 `.item()`。

禁止为了日志而反复触发 CUDA 同步。

**步骤 E：构造 Native BA 所需的完整 strength**

注意：虽然计算只使用源帧，但 Candidate BA 可能仍要求传入与原始 disparity Buffer 相同形状的 Tensor。

因此：

1. 在 GPU 创建 `zeros_like(video.disps)`。
2. 将计算好的源帧系数通过 `index_copy_` 等方式写入对应位置。
3. 非源帧保持零。
4. 维持原始 BA 参数形状。

不得为了减少 Tensor 形状而擅自修改 Native BA 接口。

**步骤 F：日志**

日志只传输：

- BA call ID。
- 源帧索引。
- 输入时间戳。
- 每帧有效像素数。
- A5 均值。
- A7 均值。
- 均值差。
- A5空间标准差。
- A7空间标准差。
- 有效支持集是否一致。
- CUDA 设备和计算精度。

禁止传输整个 Buffer 的像素数据。

允许一次性传输少量汇总统计结果。

保留 TASK011C 的所有原始约束：

# 4. 第三阶段：Fixed-State Replay

这是本任务最重要的研究设计部分。

## 4.1 研究问题

Fixed-State Replay 要回答：

**在完全相同的 BA 输入状态下，A5 的空间差异化可靠性分配，是否比 A7 的均匀可靠性分配更有效？**

它研究的是局部 BA 空间分配机制，而不是完整 SLAM 轨迹。

## 4.2 固定参考状态

使用同一序列、同一种子下的 A0 原始 DROID-W 轨迹作为参考状态来源。

A0 是原始安装版，不进行 A5/A7 干预。

在其运行过程中，记录所有符合以下条件的 BA 调用：

- FRONTEND_MAIN_LOOP_LOCAL_BA。
- 非 motion-only。
- metric_depth_reg=true。
- 属于 A7 原定干预范围。

不记录：

- Initialization。
- Second Initialization。
- Final Global BA。
- Online Global BA。
- Trajectory Filler。
- Motion-only BA。

使用实际调用记录，不根据结果挑选快照。

## 4.3 Replay 规则

对每一个固定 BA 快照：

1. 保存原始30个 Native BA 输入参数。
2. 保存必要的时间戳与源帧映射。
3. 保存 A5 原始系数场。
4. 保存 Native-valid 与 mono disparity Mask。
5. 保存 BA 所需的其他状态。
6. 为 A5 和 A7 分别创建独立 Tensor 副本。
7. 恢复相同随机数状态。
8. 使用同一 Candidate BA。
9. 只改变 prior-strength 空间分布。

A5：

```
原始 A5 空间可靠性分布
```

A7：

```
同一状态下 A5 的逐源帧均值
```

两者必须：

- 使用完全相同的30个原始 BA 参数。
- 使用相同的初始化状态。
- 使用相同的 U/UBA。
- 使用相同的权重。
- 使用相同的迭代次数。
- 使用相同的 Native Extension。
- Geometry Need=false。

A5 与 A7 必须从独立的状态副本开始。

不能先执行 A5，再拿 A5 修改后的状态执行 A7。

## 4.4 数值检查

每个 Replay 调用都必须验证：

[\
|\operatorname{Mean}(A5)-\operatorname{Mean}(A7)|\leq10^{-6}\
]

同时验证：

- 有效 Mask 相同。
- 正值支持集相同。
- A7 在有效区域内空间常数。
- 非源帧不产生先验。
- 原始 U/UBA 不发生变化。

另外增加 A5-A5 重复 Replay 对照，评估 Native 数值波动。

如果数值波动已经接近或超过 A5/A7 的差异，必须将机制结论标记为不确定。

## 4.5 研究输出

记录：

- BA 输出 Pose 差异。
- Disparity 更新差异。
- Solver 已有的残差或能量诊断（如果可用）。
- A5/A7 实际均值。
- 空间标准差。
- 每次 BA 的运行时间。
- Native 数值波动。

不允许为了获取额外指标而擅自修改 Native Solver。

**Fixed-State Replay 不产生完整轨迹，不计算它自己的 Sim3 ATE/RPE，不得称为端到端 SLAM 性能结果。**

同一序列内多个 BA 调用属于嵌套观测，不得当成独立样本扩大统计量。

## 5.3 独立运行规则

每个 Arm：

- 使用自己的初始化。
- 使用自己的关键帧选择。
- 使用自己的 BA 调用历史。
- 使用自己的轨迹。
- 不共享中间状态。
- 不强制同步关键帧。
- 不从另一个 Arm 的输出继续运行。

同一 Sequence、同一 Seed 下，各 Arm 使用相同的原始输入和配置。

但各自的内部轨迹独立演化。

**尤其注意：**

A7 只保证在自己当前 BA 状态下，与该状态的反事实 A5 均值匹配。

不保证：

A5 独立轨迹第 k 次 BA 的均值 = A7 独立轨迹第 k 次 BA 的均值。

两条轨迹的关键帧、源帧集合和 Mask 可能已经不同。

不得为了制造跨轨迹均值一致性而强制同步关键帧。

# 6. 两套实验的最终边界

| 比较维度    | Fixed-State Replay | End-to-End |
| ------- | ------------------ | ---------- |
| 初始状态    | 完全相同               | 各自初始化      |
| BA 输入   | 完全相同               | 独立演化       |
| 关键帧     | 固定                 | 各自决定       |
| A5/A7均值 | 同状态严格匹配            | 各自状态内匹配    |
| Solver  | 相同                 | 相同         |
| 轨迹      | 不生成完整轨迹            | 完整轨迹       |
| ATE/RPE | 不作为轨迹结论            | 主要评价       |
| 研究问题    | 空间分配机制             | 实际算法效果     |
| 研究地位    | 机制证据               | 主要性能证据     |

结果解释必须遵守：

**情况一：**

FSR 中 A5 优于 A7，E2E 中也优于 A7。

说明局部空间分配优势与实际轨迹收益相互支持。

**情况二：**

FSR 中 A5 优于 A7，但 E2E 没有收益。

说明局部 BA 机制可能有效，但不足以证明完整系统获益。

**情况三：**

FSR 中差异不明显，E2E 中 A5 优于 A7。

说明可能存在状态演化、关键帧选择等间接效应，不能直接归因于单次 BA 空间分配。

**情况四：**

FSR 和 E2E 均无明显收益。

不能据此直接宣称 A5/A7 等价。需要结合置信区间、数值波动和统计功效判断。
