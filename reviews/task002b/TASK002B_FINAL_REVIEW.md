# GameCam-VO Task 002B｜R2 输入一致性与离线运动评价

**结论：已完成，等待人工评审。** 在 VIPER R2 的 92 个区段中，原图身份、图像变换、共同 DROID encoder 归一化公式以及两套模型的有效相机内参均有一致性证据。固定 K 主组的差距主要出现在较长间隔：DROID-W 的平均平移和旋转 RPE 均较高。`val_007` 的位移压缩在其他序列、其他环境也可观察到；现有输出不足以判断是哪一段优化或哪个模块造成的。

## 七个审查问题

| 问题 | Task 002B 判定 |
| --- | --- |
| A. 实际预处理一致吗？ | **确认来源和几何变换。** 49,815 个 JPEG CRC/SHA 通过，92 个历史 BGR 与 RGB f32 回执跨表示一致；280 个 CPU 样本归一化后逐元素相同，Night `val_007` 与虚拟相机 `val_042` 各完成一段全量回放并匹配历史哈希。 |
| B. 归一化影响公平性吗？ | **未发现相应差异。** SLAM 送 BGR uint8、W 送 RGB float32；通道转换和 `/255` 执行位置不同，二者共同 DROID encoder 使用相同均值和标准差。GPU encoder 输入未保存；W filler 仅有完整帧数与源码证据，无独立 tensor 哈希。 |
| C. 相机内参一致吗？ | **92/92 640×360 实收向量 float32 逐位相同。** 从原 Camera CSV 复算的 49,815 行 K 与封存数组一致；名义 K 和共同运行 K 最大差 `4.053e−5 px`。SLAM 记录了缓存 K/8 的断言，W 的 K/8 有源码证据。 |
| D. 轨迹与 GT 完整吗？ | **184/184 轨迹、47/47 GT 通过身份核验。** 各模型 49,815 个有效导出位姿，0 缺失、0 无效。对应规则 `Camera ID = RGB ID−1`；未证明共同物理时钟。有效导出包含 filler，不能折算前端跟踪成功率。 |
| E. 正式 RPE 复现了吗？ | **通过。** 仅使用 SHA 锁定的 `VIPER_R1_SEGMENT_METRICS_V1`，复现 2,944 行，最大历史数值差 `1.68523e−6`（在联合容差内）；Sim(3)/SE(3) ATE 和尺度复算逐项对应。 |
| F. 五环境有什么差异？ | 固定 K 组 60 与 150 帧的平移均值及配对区间在每个环境都偏向 DROID-SLAM。旋转误差在合并组的 15–150 帧间隔也偏向 DROID-SLAM，但环境层面的区间支持不一。虚拟相机只有 2 条，单独描述。 |
| G. `val_007` 是否是个例？ | 两个重叠区间的 W/GT 幅度比为 0.450、0.484。offset=15 的事后持续压缩筛查为固定 K 27/45，排除 `val_007` 后仍为 26/44，五种环境均有案例。复发的是症状，不能由此证明共同根因。 |

## 研究判断

优先把后续诊断样本选为 `val_007`、至少一条非 Night 的复发序列及一条未压缩的对照，并在相同输入协议下同时观察平移和旋转。现有证据支持比较算法机制，对 Metric3D、U/UBA、前端对应、在线 BA 或最终 BA 尚无单独的因果证据。建议先人工审查输入证据等级、间隔及序列统计、筛查阈值和反例；后续需要观测或消融时另行批准。

本轮没有新增 GPU 请求、CUDA、SSH、模型运行、训练、消融或数据下载；只读已有本地 R2/R1、原始 RGB 和 Camera 证据，新输出仅在 Task 002B 目录。保持冻结协议，不启动 Task 003。
