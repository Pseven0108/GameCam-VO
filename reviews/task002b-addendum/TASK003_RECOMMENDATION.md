# Task 003 建议｜在同一次 stride=1 运行中定位异常阶段

**建议提交一次观测实验审批。Task 003 未启动。** `val_007` 的 RGB 312→328 已在 DROID-W 最终 BA 锚点中出现压缩（位移比 0.02615）。下一步先定位压缩首次出现的阶段，再检查非关键帧补位是否进一步改变它。现有最终轨迹无法区分前端、在线 BA、最终 BA 和补位过程各自的影响。

## 对象和控制条件

- 仅建议观测 DROID-W 的 `val_007_full_00001-00487` 一次，使用 `VIPER_MATCHED_DUAL_BASELINE_R2_V1` 完整 487 帧、640×360、`stride=1`。保持固定 K、输入顺序、实际配置、权重及 `c3414af6047d06bafc1a6645d09f23247f3b2cdc` 不变。原始 DROID-SLAM 的封存轨迹作参考。旧的 stride=4、122 帧快照仅供历史参考。
- 在独立目录记录观测。只读取和复制阶段结果，不改变缓存、采样、优化或进程设置。先核对输入哈希、帧号映射、观测开销和空间预算；无法核对是否改变运行行为时，不把结果当作机制证据。推理仅用冻结 RGB 和已批准的内参；GT 仅用于离线评分。
- 预先固定 `299→353`（包围目标段的锚点）、`312→328`（相邻锚点）、`309→325` 和 `301→353`（两类异常段）。两端在某阶段没有同时存活时标记缺失。16 和 52 帧间隔仅用于案例，正式 RPE 偏移仍为 1、15、60、150。

## 最小观测点

| 阶段 | 记录 | 可判别的现象 |
|---|---|---|
| 前端接受、拒绝或删除关键帧 | RGB ID、局部时间戳、原生可见的原因、接受时的 Pose、缓存槽与 RGB ID 对应；拒绝帧可只有事件 | 两个锚点首次同时可见时是否已经短缩。 |
| 在线 BA（仅在实际执行时）及最终 BA 之前 | 同一 RGB ID 的更新前后 Pose，以及最终 BA 入口的活跃锚点、坐标方向、四元数顺序 | 区分跟踪初值、在线调整与最终优化。 |
| 最终 BA 两次调用之后 | `dense_ba(7)` 和 `dense_ba(12)` 的同步阶段快照，记录实际调用和参数 | 定位目标位移在哪次调用时改变。 |
| Filler 初始插值及最后一次 pose-only 更新后 | 左右锚点 RGB ID、Pose、插值系数和初始 Pose，以及覆盖前的原始补位 Pose | 用同一组锚点直接区分从初值继承的异常与补位更新的增量。 |
| 最终导出 | 同帧的转换前后 Pose、关键帧覆盖来源、最终 c2w 和导出行号 | 直接验证导出环节对最终位姿的影响。 |

启动前固定复现判据。若帧号、关键区间的端点身份或压缩现象没有复现，标记 `OBSERVED_RUN_NOT_MATCHED`，不能把新运行的阶段变化归给封存结果。新运行仅在完整轨迹上拟合一次 Sim(3)，将同一尺度和旋转用于坐标规约可比的各阶段；规约变化时先核实转换，不能核实则不比较绝对位置。目标区间同时报位移长度比、位移方向、相对旋转和平移/旋转 RPE，不按阶段或局部区间重新拟合尺度。

判读：若前端锚点已短缩，优先查跟踪与初始化；若短缩始于某次 BA，后续取证集中在该次更新；若终末锚点正常而 Filler 更新导致误差加重，再优先查补位。若锚点与补位均有变化，分开量化。一次观测只提供本序列的阶段证据，无法建立跨环境因果结论，也不直接启动消融实验。
