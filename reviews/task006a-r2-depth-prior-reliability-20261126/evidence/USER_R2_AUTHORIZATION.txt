# TASK006A-R2：Metric3D 深度先验可信度研究与验证

## 一、任务背景

项目：GameCam-VO

GitHub：https://github.com/Pseven0108/GameCam-VO

研究主线：第三人称动态游戏场景下的视觉 SLAM 与相机运动估计。

当前研究阶段：TASK006A-R1 CADP 已完成 CPU 研究阶段，开始进入 R2 深度先验可信度研究。

本任务不是直接开发新的融合算法，而是研究、验证并确定 Metric3D 深度先验的可信度评估方法。

### 1.1 当前技术背景

现有系统使用：

- DROID-W：视觉 SLAM 主干。
- Metric3D V2：单目 Metric Depth Prior。
- DINOv2：现有特征及不确定性相关模块。
- VIPER：主要游戏场景测试数据集。

现有 Metric3D 配置以 `metric3d_vit_large` 为主要研究对象。

已经发现一个值得深入研究的问题：

Metric3D V2 的推理接口返回：

```python
pred_depth, confidence, output_dict = model.inference(...)
```

但当前 GameCam-VO 的深度估计接口使用：

```python
pred_depth, _, _ = model.inference(...)
```

因此，Metric3D 原生 Confidence 被直接丢弃。

相关源码：

- GameCam-VO：
  `source/DROID-W/src/utils/mono_priors/metric_depth_estimators.py`
- Metric3D：
  `mono/model/monodepth_model.py`
- Metric3D：
  `mono/model/decode_heads/RAFTDepthNormalDPTDecoder5.py`
- Metric3D：
  `training/mono/model/losses/GRUSequenceLoss.py`

Metric3D 训练代码中存在 Confidence 监督，但其输出不能直接等同于经过校准的概率或深度方差。

因此，本任务需要回答：

**Metric3D 原生 Confidence 能否在 GTA-V/VIPER 场景中识别错误深度先验？**

如果不能，是否可以利用无需训练新网络的辅助方法提高可信度评估能力？

### 1.2 研究目标

最终形成一套独立于 R1 几何可信度的深度先验可信度评估方案。

研究候选：

A. Metric3D 原生 Confidence。

B. Test-Time Augmentation（TTA）预测一致性。

C. Metric3D Depth-bin 分布不确定性。

D. 必要时研究 Gradient-based Uncertainty。

不预设最终方案，不为了组合模块而组合模块。

所有方法必须先独立验证。

## 七、阶段 R2-4：候选 A——Metric3D 原生 Confidence 验证

这是第一优先实验。

### 目标

验证原生 Confidence 是否能够预测深度误差。

### 7.1 实验设计

在具有合格 Dense Depth GT 的样本上运行现有 Metric3D。

每个像素记录：

- RGB。
- Predicted Depth。
- Ground Truth Depth。
- Native Confidence。
- Valid Mask。
- Absolute Relative Error。
- Log Depth Error。

误差：

\[
e_{\mathrm{rel}}(p)=
\frac{|D_p-D_p^{GT}|}
{D_p^{GT}+\epsilon}
\]

同时记录：

\[
e_{\log}(p)=
|\log D_p-\log D_p^{GT}|
\]

必须使用合理的有效深度范围和 GT Mask。

不能让无效深度参与统计。

### 7.2 评价指标

至少包括：

**排序能力**

- Spearman Rank Correlation。
- Pearson Correlation（辅助）。

**错误识别能力**

- AUROC。
- AUPRC。

至少研究多个高误差阈值，例如：

- Relative Error > 0.1。
- Relative Error > 0.2。
- Relative Error > 0.5。

这些阈值用于敏感性分析，不允许只挑选对结果有利的一个。

**不确定性排序评价**

- AUSE。
- AURG。
- Risk-Coverage Curve。
- Random Baseline。
- Oracle Baseline。

**校准评价**

- Reliability Diagram。
- 分桶误差统计。
- ECE（仅在定义了概率事件或完成合法概率校准后使用）。

特别注意：

原始 Confidence 不一定是概率。

先判断它的方向：

- Confidence 越高，误差是否越低？
- Confidence 越低，误差是否越高？

如果方向相反，必须记录，不得通过不透明变换隐藏问题。

### 7.3 分层评价

至少按照以下维度分组：

- 近距离。
- 中距离。
- 远距离。
- 高纹理区域。
- 低纹理区域。
- 图像边缘。
- 大面积平面。
- 物体边界。

如果 GT 支持，还要研究不同语义类别。

所有统计需要考虑帧与序列之间的相关性。

置信区间应优先采用按序列或帧分组的 Bootstrap，而不是将所有像素视为独立样本。

### 7.4 环境评价

优先关注：

- Day。
- Sunset。
- Rain。
- Snow。
- Night。

尤其关注 Night。

如果 GT 数据不具备上述所有环境，不得虚构实验结果。

可使用 VIPER 做无 GT 的分布分析，但必须与有 GT 的准确性验证分开。

## 八、阶段 R2-5：候选 B——Test-Time Augmentation 一致性

### 目标

研究原生 Confidence 以外，是否可以通过输入扰动后的预测差异发现错误深度。

### 8.1 首选方案：水平翻转

执行：

1. 原始图像输入 Metric3D。
2. 水平翻转图像。
3. 再次输入 Metric3D。
4. 将第二次深度结果恢复原方向。
5. 将两张深度图对齐。
6. 计算像素级预测差异。

定义：

\[
u_{\mathrm{flip}}(p)=
\frac{
|D_1(p)-D_2(p)|
}{
|D_1(p)|+\epsilon
}
\]

也可以研究：

\[
u_{\log}(p)=
|\log(D_1(p)+\epsilon)
-\log(D_2(p)+\epsilon)|
\]

两者都应记录。

### 8.2 必须研究的问题

- 翻转是否引入额外几何偏差？
- 恢复图像方向是否正确？
- 焦距尺度是否保持一致？
- Padding 和 Resize 是否完全一致？
- 原始图像与翻转图像的 Confidence 差异如何？
- 翻转差异是否能识别 GT 中的高误差区域？
- 翻转差异是否只集中在图像边缘？

注意：

TTA 不一致性只代表模型对输入扰动敏感。

它不等于真实误差。

模型可能在不同输入下保持一致，但始终预测错误。

### 8.3 与原生 Confidence 对比

分别评价：

A. Native Confidence。

B. Flip Disagreement。

C. Native Confidence + Flip Disagreement（仅作为离线分析候选）。

先单独评价，再研究简单组合。

组合方法必须在 Calibration Split 上确定，不能在 Test Split 上选择最优参数。

不得直接把两个信号相加就宣布获得了更好的可信度。

### 8.4 性能开销

记录：

- 单帧前向时间。
- 两次前向时间。
- GPU 显存。
- 峰值显存。
- 额外计算成本。
- 是否影响现有处理速度。

`R2_05_TTA_METRICS.csv`

## 九、阶段 R2-6：候选 C——Depth-bin 分布不确定性

### 目标

研究 Metric3D 内部深度分布是否包含比最终 Confidence 更有用的可信度信息。

### 9.1 源码研究

重点检查：

`mono/model/decode_heads/RAFTDepthNormalDPTDecoder5.py`

追踪：

- Depth Regressor。
- Depth Anchor。
- Bin Logits。
- Softmax。
- Depth Regression。
- 初始深度。
- RAFT 迭代深度。

确认实际 Bin 数量，不允许直接假设是 256。

### 9.2 候选统计量

如果能够合法读取原始深度分布，研究：

Entropy：

\[
H(p)=-\sum_k p_k\log(p_k+\epsilon)
\]

Variance：

\[
V(p)=\sum_k p_k(d_k-\bar d)^2
\]

Maximum Probability：

\[
P_{\max}=\max_k p_k
\]

Effective Number of Bins：

\[
N_{\mathrm{eff}}=\exp(H(p))
\]

其中 \(d_k\) 为实际深度 Anchor。

### 9.3 重点限制

Depth-bin 分布属于初始深度回归阶段。

最终深度还会经过 RAFT 迭代修正。

因此：

不能直接认定初始分布熵代表最终深度误差。

必须分别检验：

- 初始 Depth Error。
- 最终 Depth Error。
- Bin Entropy。
- 原生 Confidence。

研究 Bin Entropy 是否能够预测最终深度错误。

如果必须修改生产模型结构才能读取内部结果，不允许这样做。

优先使用独立研究分支、Forward Hook 或只读调试方法。

如果无法可靠获取，则记录技术限制，不要强行实现。

### 交付物

`R2_06_DEPTH_BIN_UNCERTAINTY.md`

`R2_06_DEPTH_BIN_METRICS.csv`

## 十四、停止条件

出现以下情况时，必须停止对应阶段。

### 数据问题

- GT 与 RGB 无法正确对齐。
- GT 深度单位无法确定。
- 数据损坏。
- 有效 GT 样本数量不足以支持结论。

此时不得继续给出真实准确性结论。

### 模型问题

- 无法确定实际 Metric3D 版本。
- 无法确认权重来源。
- Confidence 输出不稳定或存在异常。
- 无法区分 Depth Confidence 和 Normal Confidence。

此时优先完成源码审计，不得盲目进入融合设计。

### 工程问题

- GPU 被其他实验占用。
- 显存不足。
- 现有环境存在冲突。
- 实验需要破坏生产 Baseline。
- 实验需要修改 CUDA Kernel。

必须停止对应操作，保留现有结果。

### 研究问题

如果原生 Confidence 已经表现出稳定的排序能力，且 TTA 和其他方法没有明确增益，不需要为了完整性强行执行所有实验。

反之，如果原生 Confidence 明显失效，则需要继续研究备用方法。

每次停止都必须记录：

- 停止原因。
- 已经完成的工作。
- 尚未完成的工作。
- 是否影响最终结论。
- 下一步建议。
