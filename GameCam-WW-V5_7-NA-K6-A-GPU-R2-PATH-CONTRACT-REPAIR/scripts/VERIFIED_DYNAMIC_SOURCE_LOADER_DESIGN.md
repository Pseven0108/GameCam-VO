# Verified dynamic source import

The previous exact candidate let ordinary project imports use a SHA-verified MetaPathFinder. Installed torch.hub._import_module creates a ModuleSpec directly and calls its loader; it bypasses that finder. SourceFileLoader then probes __pycache__, even with -B. The precise ModelIOBoundary rejects this non-manifest path before Python can fall back to source.

VerifiedDynamicSourceLoader reads only a candidate-registered canonical .py file. O_NOFOLLOW, regular-file checks, kernel descriptor target checks and before/after fstat checks accompany a single read. SHA-256 is computed over that byte buffer. source_to_code compiles the same immutable byte buffer. There is no bytecode read/write and no unchecked second source read.

VerifiedSourceFinder preserves standard package ModuleSpec metadata, parent paths, relative imports, sys.modules, Python module locks and failure rollback. Normal repeated imports retain Python caching. The scoped torch.hub._import_module adapter accepts only the exact pinned Metric3D and FiT3D hubconf paths and their already-frozen legacy aliases. During that exact Hub source execution, the frozen canonical parent is temporarily inserted ahead of Torch's legacy alias and removed in finally. Submodule origins therefore remain canonical and do not gain general symlink access. CPU tests use the installed _add_to_sys_path context and MODULE_HUBCONF value. Each Hub call remains a fresh module; its temporary sys.modules entry is removed or restored after execution. restore_torch_hub restores the captured installed function. No importlib global function is patched. The ModelIOBoundary implementation is unchanged.

The separate manifest freezes every Metric3D/FiT3D Python file already trusted in the previous candidate. Candidate validation binds that manifest to source_records and to the unchanged external production-source hashes. The existing pytorch_scatter build-source closure is retained; it receives no Hub entrypoint. Unknown source, bytecode, traversal, symlinks, SHA mismatch and source replacement are rejected. Hub binding failures are published through the existing structured early Terminal path with their own failure phase.

CPU probes use the production child's main, boundary, RuntimePins and IPC. Only the authorization context and native model runtime are replaced in the CPU test process. CUDA telemetry in the supervised fixture is explicitly synthetic. The real 15 s preparation + 15 s CUDA-ready protocol, 3 s freshness, 512 MiB memory floor and cleanup logic remain unchanged. No model construction or checkpoint deserialization is tested here.

Limits: this is a Python audit boundary, not an OS/native-extension sandbox. Existing trusted environment reads are unchanged. torch.hub._import_module and CPython _ModuleLockManager are pinned private APIs; changing the interpreter/Torch version requires revalidation. The Metric3D Config.fromfile model-entry body and model constructors are outside this CPU import-only probe; config inheritance and selected type names are source-audited. No full Tracker readiness or GPU performance claim follows from these imports.
